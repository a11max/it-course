# Теоретический материал к лабораторной работе  
## «Создание диалога агентов на основе LLM»

### 1. Что такое большие языковые модели (LLM)

**Большая языковая модель (Large Language Model, LLM)** — это нейросеть, обученная на огромных объёмах текста. Она умеет предсказывать следующее слово (токен) на основе предыдущих.

Простыми словами: модель «читает» ваш запрос и по очереди генерирует ответ слово за словом, выбирая наиболее вероятные продолжения.

Примеры известных LLM: GPT, LLaMA, Qwen, Phi, Gemma и др.

В этой работе мы используем небольшую модель (например, Qwen2.5-0.5B), чтобы её можно было запускать на обычном компьютере.

---

### 2. Токенизация — как модель «читает» текст

Компьютер не понимает слова напрямую. Текст сначала разбивается на **токены** — небольшие кусочки (слова, части слов или символы).

Пример:
```
«Искусственный интеллект» → ["Искус", "ственный", " интеллект"]
```

Библиотека `transformers` делает это автоматически с помощью **токенизатора** (`AutoTokenizer`).

Основные действия:
- `tokenizer(текст)` — превращает текст в числа (токены);
- `tokenizer.decode(токены)` — превращает числа обратно в текст.

---

### 3. Генерация ответа моделью

После токенизации модель получает последовательность чисел и начинает **генерировать** новые токены один за другим.

Важные параметры генерации:

| Параметр       | Что делает                                      | Типичное значение |
|----------------|-------------------------------------------------|-------------------|
| `max_length`   | Максимальная длина всего ответа (в токенах)     | 512               |
| `temperature`  | «Креативность»: чем выше — тем разнообразнее    | 0.7               |
| `top_p`        | Ограничивает выбор только наиболее вероятными токенами | 0.9          |
| `do_sample`    | Если `True` — выбирает токены случайно (не всегда самый вероятный) | `True` |

После генерации токены снова превращаются в обычный текст с помощью `decode`.

---

### 4. Системный промпт (System Prompt)

**Системный промпт** — это специальная инструкция, которая говорит модели, **как** она должна себя вести.

Примеры:
- «Ты — учёный-оптимист. Всегда хвали возможности ИИ…»
- «Ты — скептик. Приводи контраргументы…»

Системный промпт обычно ставится в самое начало запроса. Благодаря ему одна и та же модель может играть совершенно разные роли.

---

### 5. Агент — модель с «памятью» и ролью

В лабораторной работе мы создаём класс `Agent`. Агент — это не просто вызов модели, а объект, который умеет:

1. **Хранить историю диалога** (`conversation_history`);
2. **Помнить свою роль** (через `system_prompt`);
3. **Формировать полный промпт** из системной инструкции + истории + нового сообщения;
4. **Генерировать ответ** и добавлять его в историю.

Благодаря истории агент «помнит», о чём шла речь раньше, и может поддерживать связный диалог.

---

### 6. Диалог двух агентов

Когда у нас есть два агента с разными ролями (оптимист и скептик), мы можем устроить между ними дискуссию:

1. Первый агент получает тему и говорит первым.
2. Второй агент получает историю (включая реплику первого) и отвечает.
3. Первый агент отвечает на реплику второго.
4. И так несколько раундов.

Такой подход называется **multi-agent dialogue** (диалог нескольких агентов). Он часто используется для:
- моделирования споров и дебатов;
- генерации более интересных и разнообразных текстов;
- исследования поведения моделей в разных ролях.

---

### 7. Библиотека `transformers`

Мы используем библиотеку Hugging Face `transformers` — самую популярную для работы с языковыми моделями.

Основные классы:
- `AutoTokenizer` — автоматически подбирает правильный токенизатор для модели;
- `AutoModelForCausalLM` — загружает модель, которая умеет генерировать текст (Causal Language Model).

Метод `from_pretrained(...)` может:
- загрузить модель с диска (если вы указали путь к папке);
- или скачать её с сайта Hugging Face (если вы указали имя модели, например `"Qwen/Qwen2.5-0.5B-Instruct"`).

---

### 8. Важные практические замечания

- Чем меньше модель — тем быстрее она работает и тем меньше памяти требует.
- При первом запуске модель может скачиваться несколько минут.
- Если появляется ошибка `Input length of input_ids is X, but max_length is set to Y` — значит, история диалога стала слишком длинной. Нужно увеличить `max_length` или использовать параметр `max_new_tokens`.
- На слабых компьютерах лучше использовать модели размером 0.5–1.5 млрд параметров.

---

### Краткая схема работы программы

```
Тема дискуссии
      ↓
Агент-1 (оптимист) получает тему → генерирует первую реплику
      ↓
Агент-2 (скептик) видит историю → отвечает
      ↓
Агент-1 видит ответ скептика → отвечает
      ↓
… и так несколько раундов
```

Каждый агент при генерации ответа использует:
1. Свой системный промпт (роль);
2. Всю предыдущую историю диалога;
3. Настройки генерации (temperature, top_p и т.д.).
